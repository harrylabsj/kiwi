# 向上沟通与复盘
当用户需要确认、汇报、回应批评、表达异议、协商资源，或核对上次沟通结果时使用。

依据与边界见 @references/research-notes.md、@references/safety-boundaries.md；输出复盘时按 @templates/dialogue-review.md。

## 沟通准备
确认用户要达成的具体结果、现有事实和沟通风险；缺信息时先给可修改草稿，最多问三个关键问题。
默认结构：我理解的目标 → 当前事实 → 我的建议 → 请确认的事项。语气尊重、具体，不讨好、不威胁、不操纵。
面对资源冲突给取舍；面对自身疏漏可承认具体事实并提出修复，不能让用户承担与其无关的责任。
默认只提供一个版本。新增日期、预算、人手、承诺均为待确认提议。不得自动发送、预约、投诉或联系第三方。
有报复/威胁背景时先考虑安全、合法可持有的事实记录与可信支持；不能保证某个渠道绝对安全。

## 结果复盘
用户主动提供上级新回复或交付结果后，关联旧分析和新材料。分别记录支持、推翻、仍不清楚的判断。
没有新材料则标未验证；上级接受本次交付只支持本次交付得到接受，不证明上级长期信任、晋升承诺或本产品的因果效果。
重复上传同一材料不增加独立证据。旧资料被更正后重新生成新版本，标旧结论已过时，而非悄悄覆盖。
没有明确授权不跨案例读取历史档案。只凭用户本轮提供的摘要复盘时，说明其为转述。

## 输出
沟通准备：优先行动 + 一段草稿 + 一个必要提醒。
复盘：新增事实 → 对原判断的影响 → 还缺什么 → 下一步或结束。

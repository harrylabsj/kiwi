# 领域学习

## 入口与范围

先确定用户想解决的问题和已知基础。背景未提供就标为假设。领域很宽时先画 0.1 骨架：分支回答什么问题，彼此如何相连，当前问题在哪里。地图的分支数随领域变化。

第一轮只给小地图、推荐入口和一个问题。深入时再补充：概念关系（含易混点）、判断路引、证据与争议、专家与作品入口、练习与反馈。判断路引为“触发情境 → 核心判断 → 适用边界 → 核验入口”。

不要把专家名单当成地图。需要比较分歧时使用“问题／立场与理由／最强异议／适用边界／核验入口”。区分稳定共识、条件性判断和争议；有时效或专业风险的主张按需查证。

交付物结构以设计文档第 7 节的 10 项为准，按序为：用途与边界、核心问题、概念关系、判断路引、证据与争议、专家与作品入口、AI 接口、当前学习位置、练习与反馈、继续探索。按本技能 `references/地图模板.md` 逐项填写；暂时填不了的段落保留标题并标注“待展开”，不留空白。

## 陪练与验收

在关键节点选择贴近用户目标的新案例，让用户先尝试。根据实际回答反馈概念关系和遗漏条件。理解证据分三层：看过解释、能用自己的话解释、能用于陌生案例。仅给出已观察到的层次，不生成虚构分数，不给掌握度百分比。

用户不想练时直接讲；用户迷路时指出当前位置和跨分支连接。每轮最多一个主要问题。

## 完成态与节奏

地图 v1.0 的判定标准：

| 项 | 完成标准 |
| --- | --- |
| 骨架 | 4—7 个以问题命名的分支，至少 2 条跨分支关系 |
| 深度 | 每个分支有核心概念关系和至少 1 条判断路引 |
| 检验 | 全图 3—5 条路引经过陌生案例检验，反馈已回写 |
| 边界 | 明确写出这张图不覆盖什么、哪些结论仍待核验 |
| AI 接口 | 一段可直接粘贴的地图摘要，加 3 个针对本领域的提问模板 |

达不到全部项目不算失败，如实说明完成到哪一项即可。不按完成度折算百分比，也不据此声称掌握程度。

节奏是建议而非强制，用户可以更快、更慢或中途停止：

| 阶段 | 大致会话 | 目标 | 交付物状态 |
| --- | --- | --- | --- |
| 定位与骨架 | 第 1 次 | 确定目标、边界与 4—7 个分支 | v0.1 首次生成 |
| 逐分支展开 | 第 2—4 次 | 每次补 1—2 个分支的概念关系与路引 | v0.2—v0.5 |
| 案例检验 | 第 5—7 次 | 用陌生案例试路引，回写修正 | v0.6—v0.9 |
| 收尾交付 | 最后 1 次 | 补齐 AI 接口段与待核验清单 | v1.0 |

每次会话结束都要更新交付物并交回用户，不把更新堆到最后。用户中断两周后回来，凭文件即可续接。

## 交付物与续接

交付物是一份自包含的 Markdown 文件《⟨领域⟩地图 v⟨版本⟩》，同一份文件承担三个角色：给人读的地图、跨会话的记忆载体、给其他 AI 的接口。文件开头的版本行与“当前学习位置”只记覆盖度：走过哪些分支、几条路引经过案例检验、哪些段落待展开；不写掌握度百分比，不声称掌握。

每次会话结束前更新地图并交付给用户，按宿主实际能力逐级降级，能力在运行时确认，不预先假设：

1. 宿主支持写文件：写入用户指定路径，报告实际落盘位置，并读回确认；
2. 宿主支持生成可分享链接：作为可选增强提供，不作为交付依赖；
3. 两者都不可用：在回复中输出完整 Markdown 全文（不是摘要），并明确告知“已整理，尚未落盘，请自行保存，下次带回本文件即可续接”。

全文输出是保底方式，必须始终可用；“我已记住”不能算交付。只有实际写入成功并读回核对后才能说“已保存”；失败时如实说明，并至少给出全文。

AI 接口段的最低内容：一段可直接粘贴的地图摘要（用户目标、已有基础、当前位置），加 3 个针对本领域的提问模板——要求区分共识与争议、要求给出反例或边界、要求标明核验入口。写法见模板第 7 项。

续接：用户带回地图文件时，以文件为准恢复版本、当前学习位置与待展开清单，从待展开处继续，不重画新图。没带回时，如实说明无法恢复上次的细节，只依据用户本次提供的线索重建最小骨架并和用户确认，不假装记得上一次的结论。

本技能不调用用户本机的任何命令行工具。用户想把地图归档进 dbrain、Obsidian 等个人系统时由用户自己操作，可以把整理好的格式交给用户粘贴。

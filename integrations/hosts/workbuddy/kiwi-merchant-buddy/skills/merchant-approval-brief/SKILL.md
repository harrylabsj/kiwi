# 人工审批摘要

把一项具体候选变更整理成供商家本人判断的摘要。输入应包含候选说明或 before/after 材料及当前已知状态。若缺少关键字段，标出缺项，不猜测候选状态。此技能不调用审批工具，不把聊天中的“同意”记录成已批准。

## 摘要流程

1. 确认对象、目标 SKU 或业务记录、候选标识（如果材料中有）和材料观察时间。
2. 对照变更前后值，逐字段列差异；把未变化、未知、删除和空值区分开。不能把空值解释为清除或零，除非材料明确说明。
3. 归纳可观察的影响：公开标题/价格/币种/单位/库存/成交入口变化、影响对象数、是否涉及整表替换。没有依据的影响标“未知”。
4. 检查风险和前置条件：来源是否新鲜、SKU 与单位是否明确、价格币种是否一致、有效期是否可读、审批是否仍有效、相关记录是否已变化。
5. 将可撤销性、对外可见性和失败后恢复方式分别说明。材料不足时给出待核对问题，不提出“直接批准”的结论。
6. 隔离敏感信息。可展示给商家的摘要只给出私有成本/底价检查结果和原因类别，不在可转发或买方可见文本中复述其具体数值。

## 输出模板

**候选与对象：**  
**当前状态依据：**  
**变更前 → 变更后：**  
**影响范围：**  
**前置条件核对：** 通过 / 不通过 / 未知，逐项列证据  
**主要风险：**  
**可逆性与失败恢复：**  
**需要审批人确认的问题：**  
**决策状态：** 尚未审批。此摘要不批准、不执行、不签署。

## 正反例

正例：材料显示公开价格由 CNY 80 改为 CNY 85，SKU 和单位一致，候选状态为待审批。摘要列出这两项，并说明商品公开售价会变化。

反例：材料只写“调价 5 元”，未说原价、币种、单位或加减方向。不能生成 before/after，也不能标成低风险；应列出缺失项并保持尚未审批。

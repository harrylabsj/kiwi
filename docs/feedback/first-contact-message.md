# Kiwi 首轮商家触达话术

目标：先验证真实询价场景和试装意愿，不在第一次联系时讲完整协议，也不把公开资料当作对方需求。

## 邮件 / 私信短版

主题：想了解贵司的 AI 询价场景，邀请一次 20 分钟交流

您好，我在做 Kiwi，一个让 AI 买家通过公开 Agent endpoint 发现商家、发起非绑定询价（RFQ）并读取报价的开源工具。商品、库存、底价和最终交易仍由商家自己的系统掌握。

看到贵司主要服务 [工业 MRO / 电子元器件 / 其他品类]，想请教一个很具体的问题：贵司是否有一小类标准 SKU，适合让 AI 买家先按型号、数量、交期和区域发起结构化询价？

我不是想先推销完整系统，更希望了解你们现在接收询价、整理商品数据和回复报价的流程。如果方向相关，想约 20 分钟听听实际做法；也可以先只回复：

1. 哪类商品最适合试；
2. 商品数据现在是 CSV、ERP、PIM 还是 API；
3. 你们最担心数据、报价或维护上的哪个风险。

如果现在不合适，也欢迎直接告诉我原因，我只做需求记录，不会公开贵司名称或资料。

谢谢！

## 访谈邀约确认

感谢回复。为了不占用太多时间，这次只讨论：当前询价流程、适合试验的商品、可公开字段、部署条件和最大顾虑，不要求现场安装，也不索取账号、客户资料或底价。访谈结束后我会用一句话复述理解，请你确认是否准确。

## 一次跟进

您好，补充跟进一次：我们仍在验证工业品 / 电子元器件商家是否愿意用一小组标准商品做 AI 询价试验。若贵司暂时不考虑，也请告诉我最主要的原因（数据、部署、报价责任、客户隐私或其他），这对我们决定先修什么很有帮助。若方便，回复“暂不考虑”即可，我不会继续打扰。

## 发送前检查

- 收件人和角色来自真实、合适的公开入口，不群发无关联系人；
- 不声称已有第三方采用、订单或付款能力；
- 不附商家私有信息、内部数据或未经授权的案例；
- 发送后当天把日期、渠道、原话、回复和下一步写入私有采用账本；
- 有效回复后再发 [`merchant-interview-guide.md`](merchant-interview-guide.md)，不要一次发完整协议。

# Kiwi 商家 / 集成方 20 分钟访谈提纲

目标：找出阻碍真实安装、公开 endpoint、首次 RFQ 和持续使用的事实，不把访谈变成产品宣讲。

## 访谈原则

- 先问最近一次真实采购、询价或集成经历，再介绍 Kiwi。
- 记录对方原话和实际步骤，不替对方解释协议，也不把“感兴趣”当作采用意愿。
- 不索取 token、客户资料、底价、精确库存或未公开 endpoint。
- 结束时只约定一个下一步：补数据、安排试装、提供公开 endpoint、再次访谈，或明确暂停。

## 时间安排

### 0–2 分钟：确认背景与许可

说明这是一次产品反馈访谈，不是销售承诺；询问是否可以记录要点。确认对方角色、主营品类和当前询价方式。

### 2–7 分钟：了解现有流程

1. 最近一次客户询价是怎么进来的？
2. 客户通常需要提供哪些字段，销售需要补问什么？
3. 商品数据现在在哪里：CSV、Excel、ERP、PIM、API，还是人工维护？
4. 从收到询价到给出报价，最耗时或最容易出错的环节是什么？

### 7–12 分钟：验证 Kiwi 场景

1. 如果 AI 买家通过公开 Agent endpoint 发现商品并发起非绑定 RFQ，哪类商品最适合先试？
2. 哪些字段可以公开，哪些必须始终留在商家系统？
3. 你是否能提供一小组标准 SKU 或能力清单用于试装？格式和准备成本是什么？
4. 试装时最不能接受的风险是什么：数据泄露、错误报价、维护成本、无人响应，还是其他？

### 12–16 分钟：确认接入条件

1. 是否有可运行 Kiwi Merchant 的服务器或托管环境？
2. 是否能提供域名和公网 HTTPS endpoint，或需要我们先协助？
3. 谁是接入负责人？通常多久能反馈一次安装或报价问题？
4. 如果首次接入需要 30–60 分钟，哪些步骤必须更简单？

### 16–19 分钟：确认意愿与阻断点

1. 现在最可能阻止你试装的一个原因是什么？
2. 什么结果会让你愿意继续使用 30 天？
3. 你愿意先试一个小目录，并接受一次真实 RFQ 吗？如果不愿意，原因是什么？
4. 如果今天不能试，下一次有意义的跟进是什么？

### 19–20 分钟：复述与下一步

用一句话复述：当前问题、适合试验的商品、主要风险和下一步。请对方纠正。只记录对方明确同意的下一步，不默认获得案例公开授权。

## 访谈记录字段

每次访谈结束后当天填写 [`feedback-log.md`](feedback-log.md)：

- 角色与行业；
- 真实目标和当前流程；
- 商品数据形态；
- Kiwi 漏斗阶段；
- 原话 / 事实证据；
- 主要阻断与 workaround；
- 采用评分和红线；
- 下一步、负责人、日期；
- 是否同意后续访谈或案例授权。

采用评分沿用 Phase 7 的 0–2 分标准：商品数据、采购适配、技术条件、响应承诺、真实意愿，共 10 分；评分不能替代原话和接入证据。

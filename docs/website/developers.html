一个产品。三种角色。开放组件构成。

Kiwi 是一个产品、三种角色（买家 / 商家 / 推理），由开放的组件与协议构成。

组件

四块开放组件。

组件角色一句话
Kiwi Runtime 用户侧运行时 买家代理或商家代理的执行环境：A2A、谈判、策略、审批、账本、交接。Buyer 侧提供 kiwi-buyer-mcp（MCP 宿主）与 kiwi-buyer-openclaw（OpenClaw 插件）两种薄适配器，共享同一 Buyer Core。
shopping-cli Merchant 数据引擎 商品/库存/价格/交期的本地事实层 + ERP/PIM 适配器；商家数据的权威在商家侧。
kiwi-catalog Kiwi 网络服务端 开放网络：代理注册/验证、ProductListing/CapabilityListing 发现索引、治理。
协议规范（spec/） 协议规范 KNP/1.0（成交前谈判）、KTH/0.1（安全交接）、商品条目契约——随 Kiwi 仓 spec/ 开源发布。
协议真相

诚实边界，设计使然。

直连，不经转

买家的 AI 与商家的 AI 通过 A2A 直接对话 —— 网络只做发现，绝不中转消息。

谈妥 ≠ 下单

KNP/1.0 止于非绑定协议。它不创建订单、不授权支付、不预留库存。

打开 ≠ 已付

KTH/0.1 把谈妥的条件交给真实的外部入口（结账 URL、采购单、ERP、联系人）。"已打开"不等于"已支付"。

跨供应商互操作在我们的测试栈中验证；独立第三方互操作证据仍在积累。KNP/1.0 止于非绑定共识；KTH/0.1 的"已打开"不等于"已支付"。

源码与构建

给开发者：源码，不是复制粘贴。

# Kiwi Runtime
git clone https://github.com/harrylabsj/kiwi
cd kiwi && npm install && npm run build && npm link   # 提供 `kiwi`

# shopping-cli（数据引擎；Merchant 用户由 init 自动安装）
git clone https://github.com/harrylabsj/shopping-cli
cd shopping-cli && pip install -e '.[api]'             # 提供 `shopping`

# kiwi-catalog（网络服务端，Operator/自建网络用）
git clone https://github.com/harrylabsj/kiwi-catalog
cd kiwi-catalog && pip install -e '.[api]'             # 提供 `kiwi-catalog`

普通用户接入：hermes 装 kiwi-buyer skill + MCP，或 openclaw 装 kiwi-buyer-openclaw 插件——见 买家入口 与各宿主集成文档。本页是开发者的源码位置。

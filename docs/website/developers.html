Kiwi is one product with three roles, built from four open pieces.

Kiwi 是一个产品、三种角色，由四块开放组件构成。

Components

The four pieces.

组件角色一句话
Kiwi Runtime 用户侧运行时 买家代理或商家代理的执行环境：A2A、谈判、策略、审批、账本、交接。
shopping-cli Merchant 数据引擎 商品/库存/价格/交期的本地事实层 + ERP/PIM 适配器；商家数据的权威在商家侧。
kiwi-catalog Kiwi 网络服务端 开放网络：代理注册/验证、ProductListing/CapabilityListing 发现索引、治理。
协议规范（spec/） 协议规范 KNP/1.0（成交前谈判）、KTH/0.1（安全交接）、商品条目契约——随 Kiwi 仓 spec/ 开源发布（原独立 kiwi-spec 已并入）。
Protocol truth

Honest boundaries, by design.

Direct, not relayed

Buyer and merchant agents talk directly over A2A — the network is discovery, never a relay.

Agreement ≠ Order

KNP/1.0 ends at a non-binding agreement. It creates no order, authorizes no payment, reserves no inventory.

Opened ≠ Paid

KTH/0.1 hands the agreed terms to a real external destination (checkout URL, PO draft, ERP, contact). "Opened" is not "paid".

Interop evidence: cross-vendor interoperability is verified in our own test stacks; independent third-party interop evidence is still being gathered.

跨供应商互操作在我们的测试栈中验证；独立第三方互操作证据仍在积累。KNP/1.0 止于非绑定共识——不创建订单、不授权支付、不预留库存。KTH/0.1 的"已打开"不等于"已支付"。

Source & build

For developers: code, not copy.

# Kiwi Runtime
git clone https://github.com/harrylabsj/kiwi
cd kiwi && npm install && npm run build && npm link   # 提供 `kiwi`

# shopping-cli（数据引擎；Merchant 用户由 init 自动安装）
git clone https://github.com/harrylabsj/shopping-cli
cd shopping-cli && pip install -e '.[api]'             # 提供 `shopping`

# kiwi-catalog（网络服务端，Operator/自建网络用）
git clone https://github.com/harrylabsj/kiwi-catalog
cd kiwi-catalog && pip install -e '.[api]'             # 提供 `kiwi-catalog`

Users: ordinary installation is one command on the For Buyers / For Merchants pages — no git, no source. This page is for developers.

普通用户安装见 For Buyers / For Merchants 页——发布后 npm 一条命令，不需要 git 和源码。本页是开发者的源码与代码位置。

# 商家实例配对与认领：安全设计（设计 §8.4）

状态：设计稿 + 第一期已实现（2026-09-17）。依据：[第 1 版设计](../v1-product-flow-and-onboarding-design.md) §4.2–§4.5、§8.4；[发布计划](generic-merchant-connector-release-plan.md) §3.3。

**要解决的问题**：商家把自托管实例接入网关时，如何证明「这个实例属于我」，且**不允许**任何人仅凭输入某个 `merchant_id` 或店铺链接就认领他人的实例／把他人实例挂到自己的目录账号下。

---

## 1. 威胁模型

| # | 威胁 | 缓解 |
| --- | --- | --- |
| T1 | 冒用他人 `merchant_id` 认领实例（把别人的实例挂到自己名下） | `merchant_id` **只能**来自已验证的 OAuth 会话；请求体里的任何 `merchant_id` 一律忽略 |
| T2 | 认领他人实例（把 B 的实例绑到 A 的账号下） | 绑定必须出示该实例的**内部凭据**并**探活成功**——凭据即控制权证明（设计 §4.5「不需要 Kiwi 人工批准，但要证明控制权」） |
| T3 | 把网关当 SSRF 探针（诱导网关请求任意地址/内网/云元数据） | 复用 A2A 出站守卫：非 loopback 必须 https、拒绝 userinfo、拒绝保留主机名与私网字面 IP、路径恰为 `/mcp`；探活不跟随重定向、超时、响应体上限 |
| T4 | 内部令牌经聊天/模型/日志外泄 | 令牌**只经网关托管的安全页面**提交（不进对话、不作为 MCP 工具入参，符合设计 §3.1）；落库前 AES-256-GCM 加密；错误信息与日志不回显令牌 |
| T5 | 实例被他人接管后仍持续路由 | 商家可随时解绑；重新绑定即覆盖旧凭据；网关侧按 `merchant_id` 单值覆盖（不存在多实例并存） |
| T6 | 配对码/凭据重放 | 第一期凭据本身即长期令牌（可撤销、可覆盖）；第二期配对码一次性 + 短 TTL + 绑定会话 |

**明确不做**：Kiwi 对商家自有服务的人工审批（设计 §1.2）；网关保存商家业务数据；网关成为任意 URL 代理。

## 2. 为什么绑定不能做成 MCP 工具

设计 §3.1 明确「不以聊天消息收集…商家服务器密钥」。MCP 工具入参要经过模型，令牌会被写进对话与模型上下文。因此：

- **绑定/解绑走网关托管页面**（`GET/POST /instance`），页面要求**商家的 OAuth 会话 cookie**（即第 0 版连接流程建立的那个会话）；
- 模型只能看到「已连接/未连接」这类非敏感状态（`kiwi_catalog_get_merchant_profile` 里的 `instance_connected`）。

## 3. 绑定流程（第一期，已实现）

```text
商家（浏览器，已 OAuth 连接）
  GET  /instance                 → 表单：实例 MCP 地址 + 内部令牌（password 输入）
  POST /instance/bind
        1) 会话 → merchant_id（服务端解析，忽略表单里的任何 id）
        2) URL 策略校验（复用注册表 canonicalBackendUrl：https 或 loopback http、路径 /mcp、无 userinfo/查询/片段）
        3) 探活：POST {mcp_url} initialize + tools/list，带 Bearer 令牌
           - 必须返回合法 JSON-RPC tools/list 结果（证明「地址可达 + 凭据正确 + 确为 MCP 实例」）
           - 不跟随重定向、15s 超时、响应体上限
        4) 加密存储：instance:<merchant_id> → 令牌；注册表记录 merchant_id → mcp_url
        5) 审计：绑定/解绑事件（actor = connector:<merchant_id>）
  POST /instance/unbind          → 删除注册与凭据（目录资料、关注关系不受影响）
```

要点：

- **凭据即控制权**：能出示该实例内部令牌的人就是该实例的运营者；网关不额外要求「域名所有权证明」（那是 Phase 2 的加强项）。
- **绑定即覆盖**：同一 `merchant_id` 只有一个实例（单值覆盖），不提供多实例并存，避免路由歧义。
- **不影响第 0 版**：未绑定实例的商家照常注册/发布（发布计划 §4 第 1 条）。

## 4. 第二期（待确认；涉及实例产品面变更）

| 项 | 内容 | 收益 |
| --- | --- | --- |
| 一次性配对码 | 实例侧新增 `kiwi merchant pair`（或管理页按钮）生成短 TTL 一次性码；商家把码与地址填到网关页面；网关用码向实例 `/pairing/redeem` 兑换 | 商家不再接触长期令牌；码可短时暴露 |
| 网关签发内部凭据 | 兑换时由网关生成该租户的内部令牌并推送给实例（实例落盘 0600）；轮换由网关发起 | 凭据生命周期可管理、可定期轮换 |
| 实例身份声明 | 实例新增只读工具/端点回报自己的 `owner_id`/instance_id；网关绑定前比对 | 防误配（把别的实例绑到本账号）；为将来「实例迁移」提供依据 |
| 自动轮换与吊销 | 定期轮换 + 解绑即刻失效 + 网关侧吊销列表 | 缩小长期凭据暴露窗口 |

上述三项都需要改商家实例（新 CLI/端点/工具），属于产品面变更，实现前需确认取舍：**是否接受「商家必须升级实例版本」**、以及**是否愿意让网关持有签发权**（网关可签发即意味着网关被攻破可冒充商家实例——但网关本来就持有调用凭据，风险增量有限）。

## 5. 验收

- 未登录/无会话访问 `/instance` → 403；绑定表单里的 `merchant_id` 被忽略，实际以会话为准。
- 探活失败（地址不可达、令牌错误、非 MCP 端点）→ 绑定被拒，且不写入任何凭据。
- 地址策略：`http://公网域名/mcp`、私网字面 IP、`metadata.internal`、带 userinfo/查询串的 URL 一律拒绝。
- 绑定后：`tools/list` 出现该实例的工具；解绑后消失；**第 0 版目录工具全程可用**。
- 跨商家：A 的绑定不影响 B；B 未绑定时看不到 `kiwi_merchant_*` 工具。
- 令牌不出现在日志、HTTP 响应、MCP 工具返回与审计详情中（以 grep 实测）。

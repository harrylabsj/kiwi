# 商家实例配对与认领：安全设计（设计 §8.4）

状态：设计稿 + 第一/二期已实现（2026-09-17）；**2026-09-18 起当前不采用**（见下方状态说明）。依据：[第 1 版设计](../v1-product-flow-and-onboarding-design.md) §4.2–§4.5、§8.4；[发布计划](generic-merchant-connector-release-plan.md) §3.3。

> **当前不采用（2026-09-18）。** 产品定位已收窄为
> [「网关不碰实例」](merchant-connector-deployment.md)（部署说明 §0）：网关只做第 0 版
> 目录能力，商家实例完全独立、与网关无任何连接；买家（含采购询价专家）经目录发现
> 商家后**直接**与实例做 A2A，整条链路不经过网关。
>
> **不要按本文继续实现。** 本文保留作两件事：① 万一将来确认平台连接器只能配固定
> MCP 地址、商家又无法自行暴露实例，重新评估启用时的**安全基线**——威胁模型
> T1–T6、控制权证明、最小授权结论都已论证清楚，可直接复用；② 记录当时的取舍。
> 届时需重过一遍威胁模型（尤其 T5/T6）。

**要解决的问题**：商家把自托管实例接入网关时，如何证明「这个实例属于我」，且**不允许**任何人仅凭输入某个 `merchant_id` 或店铺链接就认领他人的实例／把他人实例挂到自己的目录账号下。

---

## 1. 威胁模型

| # | 威胁 | 缓解 |
| --- | --- | --- |
| T1 | 冒用他人 `merchant_id` 认领实例（把别人的实例挂到自己名下） | `merchant_id` **只能**来自已验证的 OAuth 会话；请求体里的任何 `merchant_id` 一律忽略 |
| T2 | 认领他人实例（把 B 的实例绑到 A 的账号下） | 绑定必须出示该实例的**内部凭据**并**探活成功**；配对码路径还必须核对实例返回的 `owner_id` 与当前目录 `merchant_id` 完全一致。凭据证明控制权，身份一致性证明归属。 |
| T3 | 把网关当 SSRF 探针（诱导网关请求任意地址/内网/云元数据） | 复用 A2A 出站守卫：非 loopback 必须 https、拒绝 userinfo、拒绝保留主机名与私网字面 IP、路径恰为 `/mcp`；**解析后按已校验 IP 建连（钉住，防 DNS 重绑定）**；不跟随重定向、超时、响应体上限 |
| T4 | 内部令牌经聊天/模型/日志外泄 | 令牌**只经网关托管的安全页面**提交（不进对话、不作为 MCP 工具入参，符合设计 §3.1）；落库前 AES-256-GCM 加密；错误信息与日志不回显令牌 |
| T5 | 实例被他人接管后仍持续路由 | 商家可随时解绑；重新配对即轮换（旧凭据立即失效）；`unpair` 即吊销；网关侧按 `merchant_id` 单值覆盖（不存在多实例并存） |
| T6 | 配对码/凭据重放 | 配对码一次性 + 短 TTL + 必须已登录目录（merchant_id 来自会话）；配对凭据由实例签发、单槽轮换、可吊销 |

**明确不做**：Kiwi 对商家自有服务的人工审批（设计 §1.2）；网关保存商家业务数据；网关成为任意 URL 代理。

## 2. 为什么绑定不能做成 MCP 工具

设计 §3.1 明确「不以聊天消息收集…商家服务器密钥」。MCP 工具入参要经过模型，令牌会被写进对话与模型上下文。因此：

- **绑定/解绑走网关托管页面**（`GET/POST /instance`），页面要求**商家的 OAuth 会话 cookie**（即第 0 版连接流程建立的那个会话）；
- 模型只能看到「已连接/未连接」这类非敏感状态（`kiwi_catalog_get_merchant_profile` 里的 `instance_connected`）。

## 3. 绑定流程（第一期，已实现）

```text
商家（浏览器，已 OAuth 连接）
  GET  /instance                 → 表单：实例 MCP 地址 + 内部令牌（password 输入）
  POST /instance/bind
        1) 会话 → merchant_id（服务端解析，忽略表单里的任何 id）
        2) URL 策略校验（复用注册表 canonicalBackendUrl：https 或 loopback http、路径 /mcp、无 userinfo/查询/片段）
        3) 探活：POST {mcp_url} initialize + tools/list，带 Bearer 令牌
           - 必须返回合法 JSON-RPC tools/list 结果（证明「地址可达 + 凭据正确 + 确为 MCP 实例」）
           - 不跟随重定向、15s 超时、响应体上限
        4) 加密存储：instance:<merchant_id> → 令牌；注册表记录 merchant_id → mcp_url
        5) 审计：绑定/解绑事件（actor = connector:<merchant_id>）
  POST /instance/unbind          → 删除注册与凭据（目录资料、关注关系不受影响）
```

要点：

- **凭据即控制权**：能出示该实例内部令牌的人就是该实例的运营者；网关不额外要求「域名所有权证明」（那是 Phase 2 的加强项）。
- **绑定即覆盖**：同一 `merchant_id` 只有一个实例（单值覆盖），不提供多实例并存，避免路由歧义。
- **不影响第 0 版**：未绑定实例的商家照常注册/发布（发布计划 §4 第 1 条）。

## 4. 第二期：一次性配对码（已实现）

| 项 | 内容 | 状态 |
| --- | --- | --- |
| 出站钉住（SSRF/DNS 重绑定） | 实例地址属不可信输入：解析一次 → 校验（含「公网域名解析到 loopback」）→ **直接用该 IP 建连**（`Host`/SNI 仍是主机名），不给运行时二次解析的机会；解析失败/混入私网段一律拒绝 | **已实现** |
| 一次性配对码 | 实例侧 `kiwi merchant mcp pair` 生成短 TTL（10 分钟）、单次、只读可抄格式的码（`pairing.json` 只存 sha256，0600）；实例挂载 `POST /pairing/redeem`；网关绑定页新增「用配对码绑定」，兑换成功即写入加密保管库 | **已实现** |
| 实例身份声明 | 兑换响应携带 `owner_id` / `principal_id`，网关要求字段非空，并核对 `owner_id == 当前目录 merchant_id` 后才落库 | **已实现** |
| 能力探测（版本/工具数） | 绑定前必须实测：粘贴路径读 MCP `initialize` 的 `serverInfo` + `tools/list`；配对路径**用兑换到的凭据实调 `tools/list`**（用不了就拒绝绑定），并记录实例自报名称/版本与工具数，绑定页展示 | **已实现** |
| mTLS | 实例↔网关双向证书 | **不做**（见下） |
| 配对凭据（实例签发） | 兑换时由**实例**新签一份 `pair_…` 凭据（`paired-credential.json` 单槽、只存 sha256、0600），网关加密保存并使用；与静态 `KIWI_MERCHANT_MCP_TOKEN` 并存（组合校验器，任一通过即放行） | **已实现** |
| 轮换与吊销 | 重配对即轮换（旧凭据立即失效）；`kiwi merchant mcp unpair` 吊销；网关侧解绑同时删除自己那份 | **已实现**（商家发起；不做定时自动轮换） |
| 网关签发内部凭据 | 兑换时由网关生成租户令牌并推送给实例 | **不做**（已决定：最小授权） |

**决策（2026-09-17，按最小授权原则）**：凭据由**实例侧**签发与持有，网关不参与签发。理由是网关被攻破时只拿到「它本来就能用的调用凭据」，不额外获得签发新凭据的能力。因此不做「网关签发并推送」，也不做网关侧令牌吊销列表——吊销在实例侧（`unpair`），网关侧只需解绑自己那份。若将来产品上要求网关统一管理凭据生命周期，再评估该方案（届时需重新过威胁模型 T5/T6）。

**实例兼容性**：配对码是**增量**能力——未升级的实例仍可用「粘贴内部令牌」方式绑定（页面第一张表单）；升级后即可改用配对码。因此不强制商家升级实例版本。未上报版本的实例在绑定页显示"未上报（实例版本较旧；建议升级以获得配对码与凭据轮换）"。

**mTLS 为何不做**：实例↔网关当前是 `HTTPS + 钉住出站 + 实例签发的可轮换凭据`。再加双向 TLS 需要双方各自管理客户端证书的签发、分发、轮换与吊销（尤其商家侧要接受 Kiwi 的 CA 或反之），运维成本显著高于收益；而凭据已能做到单槽轮换与吊销。若将来出现监管或大客户要求，再评估——届时需明确证书生命周期归属。

## 5. 验收

- 未登录/无会话访问 `/instance` → 303 跳转连接流程；绑定表单里的 `merchant_id` 被忽略，实际以会话为准。
- 探活失败（地址不可达、令牌错误、非 MCP 端点）→ 绑定被拒，且不写入任何凭据。
- 地址策略：`http://公网域名/mcp`、私网字面 IP、`metadata.internal`、带 userinfo/查询串的 URL 一律拒绝；域名解析到私网/保留段或 loopback（重绑定）同样拒绝；多地址中混入私网也不放行。
- 绑定后：`tools/list` 出现该实例的工具；解绑后消失；**第 0 版目录工具全程可用**。
- 配对码：真实 CLI 生成的码可兑换一次（返回实例身份 + **新签的配对凭据**），重用与错码均被拒；过期即失效；`pairing.json` 0600 且不含明文。实例 profile 的 `owner_id` 必须与 Kiwi 目录 OAuth 返回的 `merchant_id` 相同，否则网关拒绝绑定。
- 凭据生命周期：旧静态令牌与配对凭据并存；重配对后旧配对凭据 401、新凭据 200；`unpair` 后配对凭据 401、静态令牌仍 200（真机实测）。
- 跨商家：A 的绑定不影响 B；B 未绑定时看不到 `kiwi_merchant_*` 工具。
- 能力探测：绑定页显示实例自报名称/版本与探测到的工具数；兑换到的凭据用不了时绑定被拒且不留状态。
- A/B 两实例（跨仓脚本 20 项断言）：各自配对、各自路由、A 的调用不达 B 的实例；实例重启与网关重启后凭据均无需重新配对。
- 令牌不出现在日志、HTTP 响应、MCP 工具返回与审计详情中（以 grep 实测）。

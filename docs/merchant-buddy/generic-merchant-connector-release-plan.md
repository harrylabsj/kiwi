# Kiwi 商家连接器独立发布计划与验收门槛

状态：产品路线已确认，待实现与发布验收；2026-09-17。采用**买方、商家两个连接器**，取代此前升级买方包为单一通用连接器的方案。产品基线见[第 1 版设计](../v1-product-flow-and-onboarding-design.md)。

## 1. 发布对象与已核实基础

| 对象 | 处理方式 | 入口与运行方式 |
| --- | --- | --- |
| Kiwi 采购询价（买方） | 保留已发布 ID `oc_bd73f860e3e2b5d3`、`source=kiwi-sourcing`、专家依赖及现有运行方式 | 本地 stdio；`npx @harrylabsj/kiwi@0.8.0`；当前连接层未配置 OAuth |
| Kiwi 商家运营（新增） | 独立上架，新 ID 由平台生成；拟用 `source=kiwi-merchant`，提交前核实唯一性 | 远程 HTTPS MCP + OAuth；由商家 Buddy 引导连接，覆盖第 0/1 版 |

[平台核验记录](workbuddy-connector-platform-verification-2026-09-17.md)确认买方一般版本更新入口存在，但未确认 stdio 改远程 OAuth 的兼容性。两连接器方案不依赖该迁移，因此原 WP3“买方工具远程化”移出本轮商家交付；本轮不修改买方包的传输、登录主体或状态存储。

现有 `kiwi-merchant-connector-oauth` 可作为商家包结构和工具适配的基础，但其指向 Veyquo 单实例的 URL 不能直接作为通用商家入口上架。已有网关/身份代码按新范围复核，不因本次文档修订自动删除或重写。

## 2. 商家服务拓扑

```text
采购专家 → 已发布买方连接器（kiwi-sourcing）→ 本地买方运行时
                                                ├─ 查询 kiwi-catalog 公开资料
                                                └─ 向可用商家发起合法询价

商家 Buddy → 新商家连接器（拟 kiwi-merchant）→ HTTPS 商家 MCP / OAuth 入口
                                                ├─ 注册/登录 kiwi-catalog
                                                ├─ 第 0 版：本商家公开资料发布/撤回
                                                └─ 第 1 版：安全路由到已配对的商家实例
                                                            └─ shopping-cli 与私有运营状态
```

第 0/1 版商家使用同一个商家连接器；不要求再安装独立目录连接器。两方共用目录中的公开资料和稳定 `merchant_id`，不共用访问凭据、私有任务或审批主体。

新增独立商家连接器并不消除商家之间的隔离要求。共享商家入口只从认证主体/令牌取得 `merchant_id`，按服务端已核验注册表路由；每个实例继续校验自身固定归属。不得成为任意 URL 代理，也不得默认回退到 Veyquo。

## 3. 工作包与交付顺序

1. **商家身份与第 0 版入口**：在商家 OAuth 安全页面提供注册/登录、邮箱验证、最小权限确认及返回 Buddy；复用 catalog 商家账号，签发绑定主体、`merchant_id`、scope 与目标资源的凭据。密码/验证码不进入聊天或任意商家实例。
2. **商家目录工具**：实现本商家公开资料、发布状态、确认发布/撤回等能力；草稿和注册私有字段不自动公开。无专属实例的用户照常注册发布，实时库存/询价工具明确不可用。
3. **商家实例配对与运营**：验证商家对自有服务的控制权、地址与能力，管理每租户独立凭据及撤销；保留现有 Merchant 读工具、变更候选、管理页确认与审计语义。外部自托管实例需要 SSRF/DNS 重绑定防护等实际验证，已有仅支持 loopback 的注册表不能宣称覆盖所有商家。
4. **新增商家包发布**：核对 source 唯一性、真实公网入口、OAuth 回调、最小 WorkBuddy 版本与工具声明；通过预览/审核后记录新平台 ID，将该 ID 配置给商家 Buddy。使用实际商家 source 派生 OAuth 回调；若为 `kiwi-merchant`，不能使用买方 `kiwi-sourcing` 回调。
5. **买方发现协同**：保持买方连接器原身份与 stdio。必要的 M0 搜索/FAQ/关注功能按独立兼容版本验证，不把它们误认为已在 v1.0.0 上线；采购专家不依赖新增商家连接器。
6. **7×24 验收**：商家服务由服务器运行时常驻，关闭 Buddy 后仍接待；进程/商品源失效时禁用实时报价并如实更新可询价状态，公开资料仍可查。

## 4. 发布门槛

- 新商家只安装 Buddy，经商家连接器完成注册、邮箱验证和发布，获得真实 `publication_id`；不要求专属服务器或买方连接器。
- 商家 A/B 的目录资料、实例、工具、资源、审批与日志相互隔离；令牌或参数不能切到其他租户。
- 商家 MCP 仅注册商家工具，买方连接器保留买方工具；两个包的凭据不可互作授权依据。即使用户同时安装两者，采购专家和 Buddy 的依赖仍分别配置。
- 第 0 版资料可被采购专家发现，标记来源、更新时间及 `inquiry_available=false`；RFQ 返回不可询价且不产生任务。若已发布买方包缺少发现能力，先完成对应功能的独立更新与实机验收。
- 第 1 版通过首次 OAuth、权限限制、refresh、撤销、重启续用、读操作、写候选、独立管理确认及离线恢复。
- 平台为商家包生成与买方不同的新 ID，Buddy 引用新 ID；买方原 ID/source、运行方式与专家依赖保持不变。
- 真实 HTTPS、请求限流、备份恢复、实例故障隔离及回滚方案完成验收。
- 商家公开资料与关注仍为买家主动拉取，不增加推送或关注者身份披露能力。

## 5. 待确认项及范围

需确认新增商家 source 唯一性、平台新 ID、首次绑定/注册回跳和商家工具可见性。商家多租户服务、跨服务器安全配对及现有功能接线仍需工程验收；独立连接器并不意味着现有包已能直接发布。

买方 stdio → 远程 OAuth 的平台兼容性问题保留为历史调查结果，**不再是本轮商家上架阻塞项**。未来若重新决定买方远程化，另行评审真实用户隔离、本地旧任务迁移和存量客户端升级。

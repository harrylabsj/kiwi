# Kiwi Merchant Buddy 第 0 版：AI 客服与用户主动订阅

状态：设计稿（2026-09-17）。本文件是实施依据，不代表相关服务、WorkBuddy 配置或订阅能力已经发布。

## 1. 决策与边界

方案可行，但“无需商家安装专属服务器”与“跨用户发现、订阅”是两件事：

- 第 0 版的商家可只安装 Kiwi Merchant Buddy，不安装本地 `shopping-cli`，也不部署自己的 Kiwi Merchant 实例；但必须连接共享的 `kiwi-catalog`，完成商家账号注册与公开资料发布后才会进入采购专家的发现结果。
- 商家原有的淘宝店、京东 POP 店等继续照常经营。Buddy 可协助准备商品文案、客服 FAQ、批量上架资料和运营分析；真正读取/修改这些店铺的商品或订单，需要各平台单独的官方授权连接器，不能仅靠注册 `kiwi-catalog` 获得。
- 商家在 Buddy 中整理商品上架资料、客服知识和答复草稿；这些私有内容默认只留在商家工作区或其导出文件中。
- 要让采购专家找到该商家、让买家以后主动查看更新，商家须**主动发布经过确认的公开资料**到 Kiwi 共享的目录服务。共享服务是平台基础设施，不是商家专属服务器。
- 第 0 版的 Kiwi 公开资料是商家确认的声明快照，不冒充淘宝/京东实时库存、实时价格承诺或 A2A 自动接待；Buddy 商家侧没有采购能力。第 1 版连接商家专属服务后才开放实时商家能力。
- “订阅”特指买家主动保存关注并在下次访问时拉取更新；不发邮件、短信、WorkBuddy 消息、A2A 主动消息或商家私信。

## 2. 用户路径

### 商家：制作、审核、发布

1. 安装 Buddy 后选择“注册到 Kiwi 目录”。打开 `kiwi-catalog` 的商家注册流程，完成邮箱验证，获得稳定 `merchant_id`；注册信息中的电话/邮箱默认不作为买家可见字段。此步不要求安装商家专属服务器。
2. 商家选择“制作商品资料”或“建立客服知识”，输入或上传现有淘宝/京东店的商品名称、基础属性和公开店铺链接，以及售后/服务材料。上架资料仍可用于原有店铺。
3. Buddy 使用 `ai-cs` 的决策规则整理可回答问题、缺口与转人工条件，生成 FAQ、客服回复草稿和上架资料。没有来源的价格、库存、售后承诺不得生成确定结论。
4. 商家逐条审核并勾选“公开”。Buddy 显示每条内容的来源、观察/生效时间和有效期；默认不公开客户数据、内部底价、凭据、订单或私有策略。
5. 未接入 `kiwi-catalog` 发布能力时只能导出文件，不显示“已发布”。商家认证后向目录提交商家简介、商品名等基本信息；发布成功返回 `publication_id`、公开地址和版本。仅完成账号注册、尚未发布资料的商家不会自动出现在买家搜索结果中。
6. 商家可撤回或更新公开资料；过期内容从搜索中降权或隐藏。版本历史保留审计。

### 买家：搜索、问答、主动关注

1. 买家主动召唤已发布的“Kiwi 采购询价”专家并搜索商品或商家。搜索返回两类候选：
   - `资料可查`：第 0 版公开资料，可查看商品、客服 FAQ 和联系/交接方式；不能自动发起 A2A 询价。
   - `可实时询价`：第 1 版已连接且健康的商家，可沿现有 Kiwi 流程发起 RFQ。
2. 买家点选某商家并问“保修多久？”等问题。专家只根据该商家的已发布资料回答，注明来源和更新时间；资料缺失则建议联系商家，不编造政策。
3. 买家明确选择“关注这家商家”并选关注范围（全部公开更新或某类商品）。系统记录订阅偏好。仅搜索、浏览、调用专家或发询价都**不**构成订阅。
4. 买家主动问“我关注的商家有什么更新？”时，系统按 `last_seen_at` 拉取**商家已批准公开**的动态，例如新品名称、公开服务说明或 FAQ 变化。商家内部任务、订单、询价、价格底线、未发布草稿不属于订阅内容。买家可随时取消关注；取消后不再展示该商家更新。
5. 商家仅能看到匿名汇总关注数与公开资料浏览统计，不能获得买家身份或联系信息。询价/交易阶段的必要披露遵循现有买方授权边界。

## 3. AI 客服能力：复用 `~/coding/ai-cs`

`ai-cs` 1.1.1 目前是一份 OpenClaw/Hermes 的**行为 Skill**，不是客服 webhook、会话数据库或渠道适配器。可复用的是“有据可答 / 澄清 / 超范围引导 / 转人工 / 拒绝”五种决策、知识来源优先级、敏感信息保护和缺口记录；不要声称复制 Skill 就实现了微信或 WorkBuddy 外部客服。

第 0 版分为两面：

| 使用者 | 入口 | 能力 | 结果 |
| --- | --- | --- | --- |
| 商家 | Buddy“AI 客服准备”模式 | 从商家提供的材料整理 FAQ，模拟顾客提问，起草回复，标记需人工处理的缺口 | 私有草稿；商家审核后才能成为公开知识 |
| 买家 | 采购专家中的商家资料问答 | 仅检索该商家已发布的公开 FAQ/商品说明 | 带来源与更新时间的自助答复；高风险问题引导联系商家 |

真正自动接入微信/企微/网站会话、记录客户身份、将答案发给外部客户，需要额外渠道适配器和 7×24 服务；属于第 1 版或单独的托管客服服务，不能作为第 0 版已实现能力。

## 4. 共享目录与订阅设计

现有 `kiwi-catalog` 已提供商家账号注册：注册后分配 `merchant_id` 并创建商家行；但现有买家发现主要搜索 Agent/Listing，Listing 以 publisher Agent 为前提。**注册商家账号 ≠ 已被采购专家发现**。当前仍缺“只有 Buddy、没有 Merchant Agent 的商家公开资料与商品基本信息”搜索面，也没有买家关注关系。不得为第 0 版伪造在线 Agent Card 或把静态价格标成实时报价。

现有 Listing 写入使用独立的 owner token 申请/审批流程。第 0 版新增的**基础公开资料**建议以已验证商家账号会话加显式发布确认授权，并按商家限流及审计；不要要求新用户为了录入商品名先申请用于 Agent/Listing 的 owner token。后续发布真实 Agent/Listing 时仍按现有权限模型办理。

建议在 `kiwi-catalog` 中基于已有商家账号新增独立的 `MerchantPublication`：`publication_id`、`merchant_id`、`status`、`source_kind=merchant_declared`、`merchant_display_name`、`shop_platform`、可选公开 `shop_url`、`title`（商品名）、`category`、公开商品基础字段、FAQ、`published_at`、`expires_at`、`version`。账号的私有电话/邮箱不进入此公开投影。读接口按商家/商品搜索并返回 `inquiry_available=false`；第 1 版 Merchant Agent 健康且可路由时再把它置为可实时询价。公开发布、修改、撤回必须是商家认证后的显式操作。

发布时生成只含公开字段的 `MerchantPublicEvent`（例如 `product_added`、`product_updated`、`faq_updated`、`service_notice`、`publication_withdrawn`），以 `merchant_id` + 递增版本关联公开资料。它代表商家**发布动态**，不是商家内部执行任务。买家订阅接口只返回这些事件；不提供向订阅者写消息的 API。

新增 `BuyerFollow`：`buyer_subject`、`merchant_id`、可选 `category`、`created_at`、`last_seen_at`、`consent_version`、`status`。身份优先用用户授权后稳定的 WorkBuddy `open_id`，或 Kiwi 自有买家账号；不要用设备指纹、聊天内容或专家调用次数推断身份。WorkBuddy Open API 是否允许当前专家/连接器直接取得该标识，须在预览态验证；若不能，先提供 Kiwi 自有登录/关注页面，不假设平台会自动给出买家身份。

最小接口草案（路径和身份方式需与 `kiwi-catalog` 既有 API 评审）：

```text
POST   /v1/merchant-publications           商家认证；显式发布/更新
GET    /v1/merchant-publications/search    公开检索；带来源/新鲜度/可询价标记
GET    /v1/merchant-publications/{id}      公开商品与 FAQ
DELETE /v1/merchant-publications/{id}      商家认证；撤回
PUT    /v1/me/follows/{merchant_id}        买家认证；显式关注（幂等）
GET    /v1/me/follows/updates              买家认证；仅响应主动查询
DELETE /v1/me/follows/{merchant_id}        买家认证；取消关注
```

### 第 0 版必须先打通的最小发现链路（M0）

**目标**：一个没有安装 Kiwi Merchant / `shopping-cli` 的已注册商家，录入至少一个商品名并确认公开后，买家通过现有“Kiwi 采购询价”专家搜索该商品，能看到这个商家。关注和动态拉取在 M0 之后实现，不作为首次发现的前置条件。

| 步骤 | 执行者与输入 | 系统结果 |
| --- | --- | --- |
| 1. 注册 | 商家经现有 `/portal/register` 或 `/v1/accounts/register` 注册、验证邮箱并登录 | `kiwi-catalog` 分配稳定 `merchant_id`；仅成为已注册商家，尚不进入专家搜索 |
| 2. 录入 | 商家在 Buddy 引导的目录发布页面填写公开商家名、至少一个商品名；类目、简介、已核验的淘宝/京东店铺链接可选 | 形成私有草稿；注册账户中的电话、邮箱和任何内部运营资料不自动复制到公开字段 |
| 3. 确认发布 | 商家在登录态查看公开预览并明确点击发布 | `kiwi-catalog` 校验 `merchant_id` 归属、字段与内容后写入 `MerchantPublication(status=published)`；返回 `publication_id`、版本和发布时间 |
| 4. 公开搜索 | 买家在采购专家中输入商品词，现有 `kiwi_search` 增加第 0 版公开资料查询 | 返回该商家 `merchant_id`、商家名、命中的商品名、资料来源与更新时间，并标记 `inquiry_available=false` / `资料可查` |
| 5. 查看与后续 | 买家点选商家 | 专家可展示该商家的已发布资料与公开店铺入口；不对第 0 版商家调用 `kiwi_request_quotes`，不把浏览行为记为订阅 |

M0 的接线选择是**扩展现有 `kiwi_search` 的结果集合**：它继续搜索现有 Agent/Listing，再从 `kiwi-catalog` 的第 0 版公开资料搜索接口合并结果；按 `merchant_id` 去重，同一商家若后来升级到第 1 版，显示一个商家主体并明确指出可实时询价的商品/能力。不得把第 0 版的公开资料写成虚构 Agent、在线端点或实时报价。若目录接口不可用，专家说明发现服务暂不可用，不用模型记忆补全商家。

M0 验收至少覆盖：未注册者不能发布；已注册但仅保存草稿者搜索不到；发布后用商品名能搜到正确 `merchant_id`；不同商家的同名商品都可出现；撤回/过期后不再进入正常搜索；第 0 版结果无法发起 RFQ；第 1 版现有搜索与询价链路保持可用。所有结果都显示商家声明来源与发布时间。

公开资料是商家声明内容，不是 Kiwi 背书；搜索、专家答复必须展示来源、更新时间、是否可询价。商家不能指定订阅者、给关注者写消息、购买排序或调用推送 API。发布内容需经过私密字段扫描、恶意指令隔离、长度限制、频率限制和人工/自动治理。买家问题不得直接送入商家可编辑的提示词执行路径。

## 5. 与现有 WorkBuddy 资产的接线

- Buddy 首页先展示第 0 版“注册 Kiwi 目录 / 整理现有店铺商品 / 准备客服 FAQ / 发布公开资料”；没有专属服务器时不要求绑定 Merchant MCP。已连接状态再展示现有库存、询价、审批工具。平台对首次绑定的实际行为须预览验证。
- “Kiwi 采购询价”专家保持**买方**角色。扩展其搜索结果和 Skill：先展示 `资料可查` 与 `可实时询价`；仅后者进入现有 `kiwi_request_quotes`。增加读取商家公开 FAQ、显式关注和查看关注更新的买方工具，不把商家运营工具暴露给买方。
- `kiwi-catalog` 现有账号注册和门户可作为第 0 版身份入口；需新增公开资料编辑/发布页面与面向 Buddy 的安全回跳或授权机制。Buddy 负责引导和回到应用；不要在 Buddy 配置中放共享管理员密钥或商家的目录 owner token。第 0 版不要求 `shopping-cli` 安装在用户电脑。
- 淘宝/京东店铺运营在第 0 版先以内容整理、资料导出和人工确认后的店铺后台操作为交付。自动读取订单、同步库存或直接上架必须单独取得对应平台的应用权限和商家授权，并作为明确标识的后续连接器能力交付。
- 第 1 版沿用同一 `merchant_id`，把手工声明的公开资料与实时商品源建立映射；上游事实与手工资料冲突时标识来源并让商家确认，不静默覆盖。

## 6. 实施顺序和验收

1. **第 0 版客服准备**：把 `ai-cs` 的规则改写为 WorkBuddy 可绑定的商家 Skill；提供 FAQ 模板、来源/有效期字段和五态演示。验证无知识、过期政策、退款/投诉、提示注入时不会产生虚构承诺。
2. **注册与公开发布**：复用 `kiwi-catalog` 的商家账号注册、邮箱验证和稳定 `merchant_id`；新增商品名/商家基础公开资料模型、认证、审核/撤回、事件版本和搜索；官网或 catalog 门户提供发布页面；Buddy 用胶囊引导商家填写和审核。验收为无专属服务器的商家可被公开搜索，且不得出现“在线 Agent/实时库存”标记。
3. **专家发现与问答**：更新 Kiwi 买方连接器和专家 Skill，搜索两类商家；从公开 FAQ 回答并展示来源；RFQ 对第 0 版商家必须 fail-closed。
4. **主动订阅**：实现买家显式关注、主动查询 `MerchantPublicEvent`、取消关注；审计无任何商家向关注者主动发送的通道。商家只能查看匿名汇总。新增内部任务或 RFQ 状态不应进入公开事件流。
5. **第 1 版升级**：开通 Merchant + shopping-cli + OAuth；同一商家资料升级为实时询价可达；不丢关注关系，仍保持拉取式订阅。

完成定义：全新商家只安装 Buddy，无需专属服务器即可注册 `kiwi-catalog`、制作并审核商品基础资料与客服 FAQ；确认公开后买家能通过采购专家发现并查询；买家能明确关注、主动查看公开动态并取消；商家继续经营原有淘宝/京东店铺，且无法推送、读取订阅者名单或把第 0 版资料伪装成实时库存/报价。

## 7. 需改动的模块

- `~/coding/ai-cs/skills/ai-cs/SKILL.md`：作为行为规则来源，暂不改原 Skill；新建 Kiwi/WorkBuddy 适配 Skill。
- `kiwi/integrations/hosts/workbuddy/kiwi-merchant-buddy/`：新增第 0 版模式、场景胶囊、帮助文案和状态分流；修改前核对现有工作树改动。
- `kiwi/integrations/hosts/workbuddy/kiwi-procurement-expert/`：买方公开资料问答、关注入口和第 0/1 版路由说明。
- `kiwi/src/buyer-core/`、`kiwi/src/mcp/`：公开资料检索与关注工具（买方范围），保留现有 RFQ 授权语义。
- `kiwi-catalog`：公开资料与关注持久化、公开搜索、商家/买家认证、治理和审计。
- `kiwi.harrylabsj.com` 对应官网项目：商家资料审核/发布、买家关注管理与安装说明。

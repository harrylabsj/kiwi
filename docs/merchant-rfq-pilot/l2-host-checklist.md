## 验收步骤（对应矩阵 HO-*）

### HO-01 目录网关不回退

1. 打开公共网关 `tools/list`（买方/目录侧）。
2. 核对返回仅含 `kiwi_catalog_*` 与买方工具：**不得出现** `kiwi_merchant_rfq_*`、实例地址或凭据。
3. 检查网关配置文件无商家实例上游、无实例 token。

**判定**：网关 tools/list 与配置均无实例痕迹。**证据**：tools/list 快照 + 配置核对截图。

### HO-03 授权层不混淆

1. WorkBuddy 中分别完成：Buddy 授权（商家账号）、连接器授权（token/OAuth）、管理页登录（独立口令）。
2. 走完整流程：导入 → 计价 → prepare_release。
3. 在连接器授权成功、**未**经管理页确认的状态下尝试激活发布 → 应被拒（无确认凭证）。
4. Token 模式重复第 3 步 → 结果相同。

**判定**：连接成功不等于报价批准；任何写执行都需要管理页一次性凭证。**证据**：被拒响应记录 + 管理页批准成功的对照记录。

### HO-04 撤销令牌

1. 连接器已连接且能读取询盘。
2. 在实例侧撤销连接器授权（token 轮换/吊销）。
3. 宿主再次调用任意 RFQ 工具 → 服务端拒绝（401/403）。
4. 检查宿主会话中不再出现新数据（缓存不续泄）。

**判定**：撤销后新访问全拒。**证据**：撤销时间 + 拒绝响应 + 复测记录。

### HO-06 Apps 可信确认

1. 在支持 iframe/MCP Apps 的宿主版本中打开展示资源（`ui://kiwi-rfq/*`）。
2. 通过 UI 呈现的"已批准"界面元素尝试推进发布状态 → 服务端必须仍要求管理页独立确认。
3. 对照：文本降级模式（无 Apps 的宿主）完成同一流程，事实与审批要求不缺失。

**判定**：iframe 呈现不构成身份；确认只来自管理页凭证。**证据**：两次尝试的响应记录。

### HO-10 真实任务对照（试点预演）

1. 取一份脱敏询盘与金标字段表，A（通用模型）/B（原生 WorkBuddy）/C（本产品）三组同材料执行 U01（见 task-cards.md）。
2. 操作者独立完成，记录净耗时、错误、人工干预。
3. 本步骤是 M4 退出的预演；正式对照数据归 L3 试点（≥3 商家、≥2 客户来源、≥20 询盘），不得用本步骤代替。

**判定**：C 组在实机上完整走通任务且安全行为与 L1 仿真一致。**证据**：计时表 + 操作者记录。

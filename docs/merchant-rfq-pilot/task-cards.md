# 对照任务卡（§19.3 差异化对照）

三组同材料对照，随机或轮换顺序以减少学习效应：

| 组 | 配置 | 说明 |
| --- | --- | --- |
| A 组（基线） | 通用模型 + 同样材料 + 可用工具 | 不安装本产品；给出同样的询盘材料与可用的通用工具 |
| B 组（现状） | 原生 WorkBuddy，不安装本产品 | 商家现状工作方式 |
| C 组（产品） | 本产品（Kiwi 询报价工作台私有试点） | 单商家实例直连 MCP + 三个技能 + 可信管理页 |

每组执行 U01–U05 五个任务；任务、资料、字段金标和人工审核口径三组一致。计时口径见 measurement-sheet.md。

---

## 任务卡使用规则

1. 每张任务卡只描述**客户输入**与**必须交付的结果**，不提示具体操作步骤（避免把产品用法泄漏给 A/B 组）。
2. C 组允许使用产品内全部 14 个 MCP 工具与管理页；A/B 组不提供任何 RFQ 专用工具。
3. 每任务结束立即填写 measurement-sheet.md 对应行；材料封存后由懂业务的审核人按金标字段表盲审。

---

## U01「客户这段话究竟要什么，还缺什么？」

- **客户输入**：一段真实脱敏询盘文本（含明确项与含糊项，如"尽快""便宜一点"）。
- **必须交付**：结构化需求清单、每项的原文定位、缺失项清单、待确认项清单；未知值保持未知。
- **金标字段**：见 golden-fields-template.csv 的 `need_*` 列。

## U02「这几个规格对应哪个 SKU？」

- **客户输入**：U01 材料中的规格描述 + 商家目录（三组同目录快照）。
- **必须交付**：候选 SKU 及依据；有歧义时列出候选差异而不是强行选中；关键 SKU 由人确认。
- **金标字段**：`sku_*` 列（含正确 SKU 与干扰项的判定）。

## U03「按当前条件出一版报价。」

- **客户输入**：U01/U02 已确认字段 + 已授权价格 + 税/运费规则（三组同规则）。
- **必须交付**：含数据时点、价格口径（含税/未税）、税率、运费、交期、有效期的完整报价；金额与金标算术一致。
- **金标字段**：`price_*` 列（单价/优惠/税额/运费/总额，以分为单位核对）。

## U04「客户改了数量/地址，重新报。」

- **客户输入**：在 U03 之后追加一条变更消息（数量或收件地址变化）。
- **必须交付**：新版本报价；与旧版的逐项差异说明；旧版失效原因说明；不得声称已撤回客户手中的旧文件。
- **金标字段**：`diff_*` 列（变化项与失效原因表述）。

## U05「这版可以发给客户了。」

- **客户输入**：操作者决定发布 U04 产出（或 U03，若 U04 被判定不可用）。
- **必须交付**：可信管理页确认后的固定文件；导出与发送状态分开；发送记录引用操作者证据。
- **金标字段**：`release_*` 列（批准记录、文件摘要、导出/发送状态语义正确性）。

---

## 评分与盲审（§19.3）

- 准确性由懂业务的审核人按金标字段表盲审固定字段；**不得用另一个模型"看起来更专业"的评价作为唯一裁判**。
- 每个字段：对 / 错 / 不可判定（不可判定计入错误率分母）。
- 主观评价单独立列，不进入主要指标。

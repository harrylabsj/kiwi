# Merchant Cloud：A2A nonce 存储

签名模式在运行时数据目录使用 `open-inquiry-nonces.sqlite`。可信签名（含支付宝私有读取）和开放询价各有独立的 100,000 条配额，保留 30 分钟。两类配额独立，但仍共用 SQLite 文件和磁盘。旧版共享表中的有效记录继续用于识别重放，不占用新配额；过期后会在后续写入时清理。

- 可信签名实际重复时仍返回 `401 replay_detected`；支付宝私有读取的常规鉴权或绑定失败仍统一返回 `404 collection_unavailable`。
- 验签成功后若无法新增 nonce（容量已满、数据库打开或写入失败），运行时拒绝该请求，返回 `503 temporarily_unavailable`、`Retry-After: 60` 和 `retry_after: 60`（秒）。客户端退避后重新签名；没有通过鉴权的请求不会进入协议处理。私有读取在检查协议或收款配置前返回该状态。
- 监控 `a2a_nonce_store_unavailable` 告警，按 `scope=signed|open_inquiry` 和 `reason=capacity|open|storage` 区分。日志对同一类告警每分钟至多记录一次，不包含 nonce、密钥或文件路径。
- `capacity`：降低相应通路的流量，等待记录自然到期（最长 30 分钟）；退避时间不是恢复承诺。开放询价持续异常时可按既有授权开关暂停。`open` / `storage`：检查运行时目录的权限、挂载、磁盘空间及 SQLite 可写性。不要为恢复容量删除数据库或有效行，否则会丢失防重放状态。
- 升级保留数据库，先停止旧版本写入，再启动新版本。旧版本不认识新配额表，不应混跑或直接回退；如确需恢复旧版，应先停止接收新签名请求并等待最后一次写入的 nonce 防重放窗口结束（30 分钟），再启动旧版。
